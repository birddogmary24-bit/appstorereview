## 1. 데이터 수집 정책

### 1.1 수집 대상 및 범위

| 항목 | 정책 |
|------|------|
| 수집 플랫폼 | Google Play Store, Apple App Store |
| 수집 언어 | 한국어(ko) 전용 |
| 수집 국가 | 한국(kr) 전용 |
| 수집 정렬 | 최신순 |
| 수집 최대 건수 | Google Play: 앱당 최대 1,500건 (15페이지 × 100건) |
| | App Store: 앱당 최대 500건 (10페이지 × 50건) |

### 1.2 수집 주기 정책

| 정책 | 내용 |
|------|------|
| 최소 수집 간격 | 앱당 1일 1회 (UI 레벨 제어) |
| 권장 수집 주기 | 주 1회 (Cloud Scheduler 자동화) |
| 전체 수집 시 앱 간 간격 | 5초 |

> **이유**: 앱스토어 API 과부하 방지 및 스크래핑 차단 예방

### 1.3 중복 제거 정책

- 고유 키: `store + id` (예: `google-play-abc123`)
- 기존 수집된 리뷰와 비교하여 신규 리뷰만 AI 분석 대상으로 처리
- 이미 분석된 리뷰는 재분석 없이 유지 (AI 비용 절약)

### 1.4 외부 서비스 의존성

| 서비스 | 용도 | 장애 시 영향 |
|--------|------|------------|
| `google-play-scraper` | Google Play 리뷰 수집 | 해당 스토어 수집 불가 |
| `app-store-scraper` | App Store 리뷰 수집 | 해당 스토어 수집 불가 |
| Google Gemini API | AI 감성 분석 | 별점 기반 폴백으로 전환 |
| Google Cloud Storage | 데이터 저장 (프로덕션) | 서비스 전체 중단 |

## 2. AI 분석 정책

### 2.1 분류 원칙 (절대 규칙)

> 별점은 AI의 판단보다 우선한다.

| 별점 | 대분류 |
|------|--------|
| 3점, 4점, 5점 | 반드시 **칭찬** |
| 1점, 2점 | 반드시 **불만** |

- AI가 별점에 반하는 분류를 제안하더라도 별점 기반 대분류를 강제 적용
- AI는 세부 사유(subCategory) 선택에만 관여

### 2.2 세부 분류 범위

AI는 아래 사전 정의된 목록에서만 세부 사유를 선택한다. 목록 외 임의 분류 불가.

**칭찬 세부 사유 (7종):**
1. 오리지널 콘텐츠
2. 화질/재생 품질
3. UI 편리성
4. 콘텐츠 다양성
5. 합리적 가격
6. 자막/더빙 품질
7. 기타 칭찬

**불만 세부 사유 (8종):**
1. 플레이어/재생 오류
2. 광고 관련 불만
3. 요금/결제/구독
4. 콘텐츠 부족/불만
5. UI/UX 불편
6. 앱 안정성(크래시/버그)
7. 자막/더빙 품질
8. 기타 불만

**기타 세부 사유 (3종):**
1. 단순 문의
2. 기능 제안
3. 미분류

### 2.3 AI 실패 처리 정책

| 상황 | 처리 방식 |
|------|-----------|
| API 응답 오류 | 최대 3회 재시도 |
| Rate Limit (429) | 지수 백오프: 30초 → 60초 |
| 3회 모두 실패 | `subCategory: "분석오류"` 태그 부여, 별점 기반 대분류 적용 |
| API 키 미설정 | 전체 리뷰를 별점 기반 자동 분류로 대체 |
| JSON 파싱 실패 | 해당 배치 재시도 또는 폴백 |

### 2.4 배치 처리 정책

| 항목 | 값 |
|------|-----|
| 배치 크기 | 50건/API 호출 |
| 배치 간 대기 | 유료 모드: 2초, 무료 모드: 6초 |
| 최대 입력 리뷰 텍스트 길이 | 150자 (인사이트 샘플) |

### 2.5 인사이트 생성 정책

- 분석 기간: 최근 6개월 슬라이딩 윈도우
- 현재 3개월 vs 이전 3개월 비교
- 스파이크 감지 기준: 이전 대비 **1.5배 이상 증가** + **최소 5건 이상**
- 인사이트 1건당 세부 사유별 최대 5건 리뷰 샘플 참조

## 3. 보안 정책

### 3.1 API 접근 제어

| API 유형 | 인증 방식 |
|----------|----------|
| 조회 API (GET) | 인증 없음 (공개) |
| 수집/분석 API (POST batch) | 비밀번호 필수 |
| 재분석 API (POST reanalyze) | 비밀번호 필수 |
| 인사이트 생성 API (POST insights) | 비밀번호 필수 |

### 3.2 비밀번호 정책

| 항목 | 정책 |
|------|------|
| 저장 방식 | Salted SHA-256 해시 (`salt_hex:hash_hex`) |
| Salt 크기 | 16바이트 랜덤 |
| 전송 방식 | HTTPS POST Body JSON |
| 소스코드 저장 | **절대 금지** |
| 환경변수 키 | `UPDATE_PASSWORD_HASH` |
| 인증 실패 응답 | HTTP 401 |

**비밀번호 해시 생성 명령:**
```bash
node -e "const c=require('crypto'),s=c.randomBytes(16),h=c.createHash('sha256').update(Buffer.concat([s,Buffer.from('YOUR_PASSWORD')])).digest('hex');console.log(s.toString('hex')+':'+h)"
```

### 3.3 시크릿 관리 정책

| 항목 | 정책 |
|------|------|
| API 키 저장 | 환경변수만 사용 (`GEMINI_API_KEY`) |
| 버킷명 저장 | 환경변수만 사용 (`GCS_BUCKET_NAME`) |
| `.env` 파일 | Git 추적 제외 (`.gitignore` 등록) |
| 소스코드 내 하드코딩 | 절대 금지 |
| Service Account Key | Git 추적 제외 (`*-sa-key.json`, `*.p12`) |

### 3.4 개인정보 처리 정책

| 데이터 | 처리 방식 |
|--------|----------|
| 리뷰 작성자명 | 수집 및 저장 허용 (공개 정보) |
| Excel 내보내기 | 작성자명 **제외** |
| 리뷰 내용 | 수집 및 저장 허용 (공개 정보) |
| 사용자 이미지 URL | 수집되나 UI에 미표시 |

## 4. 데이터 저장 정책

### 4.1 저장소 구조

| 환경 | 저장소 | 경로 |
|------|--------|------|
| 개발 (로컬) | 로컬 파일시스템 | `data/{appId}/` |
| 프로덕션 | Google Cloud Storage | `gs://{GCS_BUCKET_NAME}/{appId}/` |

**파일 구조:**
```
{appId}/
├── reviews.json    # 전체 분석된 리뷰 배열
├── insights.json   # 월별 인사이트 배열
└── status.json     # 마지막 업데이트 시각
```

### 4.2 데이터 보관 정책

| 항목 | 정책 |
|------|------|
| 리뷰 데이터 | 영구 보관 (별도 삭제 정책 없음) |
| 인사이트 데이터 | 영구 보관, 같은 월 재생성 시 덮어쓰기 |
| GCS 버전 관리 | 최대 5버전 보관 후 자동 삭제 (lifecycle 정책) |
| GCS 백업 | 별도 버킷에 동기화, 30일 후 자동 삭제 (backup lifecycle 정책) |

### 4.3 환경 구분 정책

| 조건 | 저장소 |
|------|--------|
| `NODE_ENV=production` + `GCS_BUCKET_NAME` 설정 | GCS 사용 |
| 그 외 | 로컬 파일 사용 |

## 5. 비용 관리 정책

### 5.1 AI 비용 최적화

| 정책 | 내용 |
|------|------|
| 신규 리뷰만 분석 | 기존 분석된 리뷰 재분석 금지 |
| 인사이트 샘플 제한 | 세부 사유당 최대 5건, 150자 이내 |
| 무료 티어 대응 | `GEMINI_FAST_MODE=false` 시 6초 배치 간격 |
| 모델 선택 | Gemini 2.0 Flash (성능 대비 저비용) |

### 5.2 인프라 비용 정책

| 서비스 | 정책 |
|--------|------|
| Cloud Run | 무료 티어 내 운영 (요청 기반 과금) |
| GCS | 무료 5GB 이내 유지 (JSON 데이터, 수 MB 수준) |
| 비용 초과 시 | GCS 버킷 lifecycle 정책으로 자동 정리 |

## 6. 운영 정책

### 6.1 수집 실패 대응

| 상황 | 대응 |
|------|------|
| 스크래퍼 오류 | 해당 스토어 건너뛰고 다음 앱 진행 |
| AI 분석 오류 | `분석오류` 태그 부여 후 계속 진행 |
| 전체 실패 | 오류 로그 확인 후 수동 재실행 |

### 6.2 재분석 정책

- `분석오류` 태그가 붙은 리뷰만 대상
- POST `/api/{appId}/reanalyze` 호출 (비밀번호 필요)
- 정상 분석된 리뷰는 재분석 대상에서 제외

### 6.3 인사이트 재생성 정책

- 같은 월의 인사이트를 재생성하면 **기존 데이터 덮어쓰기**
- 데이터 추가 수집 후 인사이트를 재생성하는 것이 권장 흐름
